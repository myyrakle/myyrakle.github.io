Envoy Gateway는 쿠버네티스 환경에서 사용할 수 있는 envoy 기반 프록시 스택이다.  
완전한 오픈소스다.  

envoy를 게이트웨이 형태로 배포하고, 서비스들 게이트웨이 route 형태로 갖다 붙이는 기능을 제공한다.  

더불어 envoy에서 지원하는 고급 로드밸런싱 알고리즘, rate limit, SSL 및 보안 인가 처리 등 게이트웨이에 필요한 것들은 대개 다 지원한다.  

그냥 간단한 것만 써도 된다면 traefik을 쓰면 되고, 더 고급 LB 기능들이 필요하다면 이게 더 적절하다.  

<br>

<br>

## 설치

helm으로 까는게 편하다.  

```javascript
helm install eg oci://docker.io/envoyproxy/gateway-helm --version v1.9.1 -n envoy-gateway-system --create-namespace
kubectl wait --timeout=5m -n envoy-gateway-system deployment/envoy-gateway --for=condition=Available
```

## 게이트웨이 클래스 정의

이것부터 만들어야 한다. 어떤 게이트웨이 구현체를 사용할 것인지를 지정하는 카테고리 값이다.  

```javascript
kubectl apply -f gateway-class.yaml
```

```javascript
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: eg
spec:
  controllerName: gateway.envoyproxy.io/gatewayclass-controller
```
이렇게 만들면 eg라는 이름으로 게이트웨이를 생성했을때, envoy controller 구현체가 자동으로 붙는 것이다.

## 게이트웨이 생성

이게 실질적인 프록시/게이트웨이를 생성하는 시점이다.  
방금 정의한 class를 가지고 적당히 정의해주면 된다.  

```javascript
kubectl apply -f public-gateway.yaml
```

```javascript
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: public-gateway
  namespace: default
spec:
  gatewayClassName: eg
  listeners:
    - name: http
      protocol: HTTP
      port: 80
```

## Route 생성

당연히 게이트웨이만 덜렁 있다고 뭐가 되진 않는다.  
실제로 서비스를 붙이는 것은 HTTPRoute라는 리소스를 통해 처리된다.  

하나의 게이트웨이에는 여러개의 HTTPRoute를 붙여서 사용할 수 있다.  

다음은 nginx 하나 띄워서 붙이는 간단한 구성이다.  

```javascript
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-test
  namespace: default
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx-test
  template:
    metadata:
      labels:
        app: nginx-test
    spec:
      containers:
        - name: nginx
          image: nginx:1.27-alpine
          ports:
            - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: nginx-test
  namespace: default
spec:
  selector:
    app: nginx-test
  ports:
    - port: 80
      targetPort: 80
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: nginx-test
  namespace: default
spec:
  parentRefs:
    - name: public-gateway
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /
      backendRefs:
        - name: nginx-test
          port: 80
```
이 경우에는 nginx-test라는 서비스를 가리키고, 그걸 게이트웨이의 루트 패스로 붙이도록 했다.  
prefix는 원하는대로 붙이면 된다.

## BackendTrafficPolicy

이건 LB 규칙을 지정할 수 있는 별개 리소스 단위다.  
로드밸런싱 알고리즘을 여기서 고를 수 있다.  

```javascript
apiVersion: gateway.envoyproxy.io/v1alpha1
kind: BackendTrafficPolicy
metadata:
  name: nginx-test
  namespace: default
spec:
  targetRefs:
    - group: gateway.networking.k8s.io
      kind: HTTPRoute
      name: nginx-test
  loadBalancer:
    type: RoundRobin
```
이건 HTTPRoute 단위에 종속되며, 여기서 설정한 값에 따라서 요청 분산 방식이 달라진다.  

RoundRobin, Random, LeastRequest 등이 지원된다.
